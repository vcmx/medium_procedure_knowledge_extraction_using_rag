# ADR 003: RAPTOR-based Chunking Strategy

## Status

Proposed

## Context

The current system uses a section-based chunking strategy for technical manuals, where chunks are created at section boundaries. While this approach works well for basic document organization, technical manuals often have complex hierarchical structures and procedural relationships that could benefit from more sophisticated chunking.

## Decision

We propose to enhance the chunking strategy by incorporating RAPTOR (Recursive Abstractive Processing for Tree-Organized Retrieval) alongside the existing section-based approach. This hybrid strategy will better handle the hierarchical nature of technical manuals while maintaining the benefits of section-based chunking.

## Consequences

### Positive

1. **Enhanced Hierarchical Processing**
   - Better representation of document structure
   - Improved context preservation across related sections
   - More natural organization of procedural content

2. **Improved Context Understanding**
   - Each level of the hierarchy gets its own summary
   - Better understanding of relationships between procedures
   - Maintained context when moving between related sections

3. **Better Content Organization**
   - Natural tree structure for navigation
   - Preserved sequential ordering within procedures
   - Clear relationships between related content

4. **Enhanced Retrieval**
   - More precise search results
   - Better understanding of query context
   - Natural grouping of related content

### Negative

1. **Implementation Complexity**
   - More complex chunking logic
   - Additional processing overhead
   - Need to maintain both chunking strategies

2. **Storage Overhead**
   - Additional metadata for hierarchical structure
   - Storage of summaries at different levels
   - More complex indexing requirements

3. **Processing Time**
   - Additional time for recursive processing
   - More complex summarization at each level
   - Increased processing overhead

## Implementation Details

1. **Chunking Process**
   - Maintain section-based chunking for basic structure
   - Apply RAPTOR processing to create hierarchical relationships
   - Generate summaries at each level of the hierarchy
   - Preserve sequential ordering within procedures

2. **Data Structure**
   ```python
   class RaptorChunk:
       text: str
       summary: str
       level: int
       parent_id: str
       children: List[str]
       metadata: Dict[str, Any]
       images: List[Tuple[str, str]]  # (image_path, caption)
   ```

3. **Integration Points**
   - Marker for initial document processing
   - Florence-2 for image captioning
   - Vector database for embeddings
   - Graph database for relationships

## Alternatives Considered

1. **Pure Section-based Chunking**
   - Pros: Simpler implementation, lower overhead
   - Cons: Less context preservation, poorer handling of relationships

2. **Pure RAPTOR Chunking**
   - Pros: Better hierarchy handling, improved context
   - Cons: More complex, higher overhead

3. **Fixed-size Chunking**
   - Pros: Simple implementation, predictable chunks
   - Cons: Poor handling of document structure, context loss
